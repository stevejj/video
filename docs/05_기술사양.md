# 05. 기술 사양 (초안 v0.1)

> 2026-09-16 Kling MCP `who_am_i` 조회 결과 기준. MCP 버전 1.3.2.
> 조회 시 "툴 목록이 갱신됐으니 호스트에서 Kling MCP를 재연결하라"는 메시지가 있었음 → 다음 세션 시작 시 재연결 필요.
> 잔여 크레딧 391 (멤버십 Standard).

## 1. 영상 생성 (image_to_video) 후보

| 모델 | 시작+끝 프레임 | 캐릭터 등록(Element) | 길이 | 해상도 | 특징 | 용도 |
|---|---|---|---|---|---|---|
| kling-video-v3_0 | ✅ first+tail | ✅ | 3~15초 | 720p/1080p/4k | 멀티샷, 네이티브 오디오(끌 수 있음) | **본편 1순위** |
| kling-video-v3_0_omni | 참조 이미지 최대 7장 | ✅ | 3~15초 | ~4k | 멀티모달 참조 | 투샷·소품 많은 샷 |
| kling-video-v3_0_turbo | 시작 프레임만 | ❌ | 3~15초 | ~1080p | 저렴, 단일 이미지 | 동작 사전 1차 테스트 |
| kling-video-v2_6 | ✅ | ❌ | 5/10초 | ~1080p | 오디오 | 예비 |
| kling-video-o1 | 참조 최대 7장 | ✅ | 3~10초 | ~1080p | 일관성 강조 | 비교 테스트 |

기본 설정(안): v3_0, 5초, 1080p(테스트는 720p), enable_audio=false, prefer_multi_shots=false(샷은 우리가 나눈다), first_image+tail_image 필수.

## 2. 모션 컨트롤 (motion_control)

- kling-video-v2_6, kling-video-v3_0. 입력: 캐릭터 이미지 + 참조 동작 영상(업로드 또는 저장된 motionId).
- motionDirection: image_direction(캐릭터 이미지의 방향 유지) / motion_direction(참조 영상의 방향 따름).
- 용도: 걷기, 문 밀기, 앉기 같은 **물리 동작을 사람이 찍은 영상으로 강제**. 현실감 보강의 핵심 후보(Q42).

## 3. 이미지 생성 (image_to_image, Kling MCP 안에서 호출) — 사용 안 함(Q44 확정: 이미지는 Gemini에서 직접)

| 모델 | 참조 장수 | 해상도 | 비고 |
|---|---|---|---|
| gemini-3-pro-image (Nano Banana Pro) | 최대 10 | 1k/2k/4k | 프레임 생성 1순위 후보 |
| gemini-3.1-flash-image (Nano Banana 2 Flash) | 최대 10 | ~4k | 저렴, 대량 초안 |
| kling-image-v3_0_omni | 최대 10 + Element | ~4k | 시리즈 생성(story_mode) |
| kling-image-o1 | 최대 10 + Element | ~2k | 정밀 편집·스타일 유지 |

→ 크레딧이 들기 때문에 쓰지 않는다. 이미지는 사용자가 Gemini 앱에서 생성해 업로드하고, Kling은 영상 전용으로 쓴다. 표는 참고용으로만 남긴다.

## 3a. Kling MCP 호출 규칙 (who_am_i에서 확인한 사실)

### 파일 업로드
- 로컬 이미지는 `file_upload`로 티켓을 받아 올린 뒤 반환된 URL만 입력으로 쓸 수 있다. 로컬 경로·외부 URL 불가(이전 Kling 작업이 만든 URL은 그대로 사용 가능).
- 이미지 규격: PNG/JPG, 4K 미만, 30MB 이하, 가로세로비 1:2보다 길쭉하면 안 됨. 우리 프레임(768x1376 = 1:1.79)은 통과.
- 같은 파일은 재업로드하지 말고 URL 재사용.

### 프롬프트 안에서 참조 표기
- 멀티 이미지 모델(v3_0_omni, o1): 입력 image_1..image_7을 프롬프트에서 `图片1`..`图片7`로 지칭한다. (중국어 표기 그대로 써야 함)
- 캐릭터 등록(Element)을 쓸 때: 프롬프트에 `<<<id>>>`를 쓰고, `elements` 인자에 `[{"id":"...","bindName":"Changsu"}]`를 넘긴다. 같은 id를 여러 번 참조 가능.
- v3_0(시작+끝 프레임 모델)은 프롬프트가 선택 사항이며 "입력 이미지가 주 동인". 비워두면 순수 이미지 애니메이션.

### 캐릭터 등록 (element_create)
- 이미지 서브젝트: 커버 1장 + 보조 1~3장. 태그 필수(Characters / Animals / Items / Costumes / Scenes / Effects / Others).
- 비디오 서브젝트: 3~60초, fps 23.8 초과, 짧은 변 700px 이상, 4K 이하, HDR 불가. v3_0·v3_0_omni에서만 사용 가능.
- 우리 계획: 팽창수·팽미순 각각 커버=고해상도 정면, 보조=3/4 좌, 측면, 뒷모습으로 등록(Q43 승인 후). 태그 Characters.
- 등록 후에도 "element id를 버리고 커버 이미지만 쓰는" 식으로 퇴화시키지 말 것(도구 설명에 명시).

### 모션 컨트롤 (motion_control)
- 입력: 캐릭터 이미지 1장 + 참조 동작 영상(업로드) 또는 저장된 motionId. 둘 중 하나만.
- motionDirection: `image_direction`(캐릭터 이미지의 방향을 따름, 동작 3~10초만 지원) / `motion_direction`(참조 영상의 방향을 따름).
- 참조 영상은 "사람 또는 동물이 선명한" 이미지에 적용. 우리 캐릭터가 '동물'로 인식되는지는 테스트 필요.

### 오디오
- v2_6: 오디오는 1080p에서만, **끝 프레임과 함께 쓸 수 없음**. → 시작+끝 프레임을 쓰는 우리 파이프라인에서는 오디오 끔.
- v3_0: enable_audio 기본 false. 그대로 둔다.

### 멀티샷
- v3_0의 `prefer_multi_shots` 기본값이 **true**다. 우리는 샷을 직접 나누므로 **명시적으로 false**로 넘긴다. (켜두면 모델이 임의로 컷을 나눠 연속성이 깨질 수 있음)

### 호출 절차 (내가 실행)
1. `file_upload`로 시작·끝 프레임 업로드 → URL 확보
2. `image_to_video` 호출: model=kling-video-v3_0, inputs=first_image/tail_image, arguments=prompt/duration/resolution/prefer_multi_shots=false/enable_audio=false(/elements)
3. generation_id로 `query_tasks` 폴링 → 결과 URL 다운로드 → 저장소 `outputs/`에 저장
4. 검수 체크리스트 통과 시 채택, 아니면 원인 기록 후 재생성(샷당 상한 Q30)

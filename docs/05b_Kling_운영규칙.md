# 05b. Kling 운영 규칙 (초안 v0.1)

> `05_기술사양.md`(무엇이 가능한가)와 `05a_Kling_프롬프트_가이드.md`(어떻게 쓰는가)에 이어, **실제로 돌릴 때 지키는 절차**를 정한다.
> 모든 Kling 호출은 크레딧이 든다. 이 문서의 절차를 벗어난 호출은 하지 않는다.

## 1. 샷 유형별 기본 설정

| 샷 유형 | 예 | 모델 | 입력 | 길이 | 해상도 | 프롬프트 핵심 |
|---|---|---|---|---|---|---|
| 정지 컷 | 서서 바라봄, 리액션 확대 | kling-video-v3_0 | 시작 프레임만 (끝 = 시작과 동일하므로 생략 가능) | 3 | 1080p | `holds the pose, only breathing and a blink`, 카메라 고정 |
| 미세 동작 | 고개 돌림, 끄덕임, 말하기, 먹기(오물오물) | v3_0 | 시작 + 끝 | 3~5 | 1080p | 부리·볼 문구, 끝 자세 |
| 이동 동작 | 걷기, 앉기, 일어서기, 문 밀기, 문턱 통과 | v3_0 | 시작 + 끝 **필수** | 5 | 1080p | `by the end ...` 끝 상태, 동작 역학 한 문장 |
| 둘 컷 | 나란히 서기, 마주 보기 | v3_0 (+Element 2개) | 시작 + 끝 | 3~5 | 1080p | 부리 움직이는 캐릭터 최대 1명, 좌우 고정 |
| 참조 많은 컷 | 소품 여러 개 + 둘 | v3_0_omni | image_1(시작) + 참조 최대 6 | 5 | 1080p | `图片N` 지칭 |
| 인서트 | 소품, 날개+물건 | v3_0 | 시작 (+끝) | 3 | 1080p | 캐릭터 없거나 일부만, 물건 개수 고정 |

공통 고정값: `prefer_multi_shots=false`, `enable_audio=false`, `imageCount=1`. 10초 이상은 사용자 승인 없이 쓰지 않는다.
테스트 성격의 첫 실행(새 유형의 샷을 처음 만들 때)은 720p로 1회 확인 후 1080p로 본 생성한다. (Q29)

## 2. 입력 준비

- 프레임 규격: 9:16, 1080x1920 이상, PNG. Kling 제한(4K 미만, 30MB 이하, 비율 1:2 이내) 통과 확인.
- 파일명 규약: `outputs/<에피소드>/<컷번호>/start_v<n>.png`, `end_v<n>.png`. 예: `outputs/ep01/2-03/start_v1.png`
- 시작·끝 프레임은 06 체크리스트 A를 **먼저 통과**한 것만 업로드한다. 프레임이 불합격이면 영상은 만들지 않는다.
- 업로드 URL은 `outputs/<에피소드>/<컷번호>/meta.json`에 기록하고 같은 파일은 재업로드하지 않는다.

## 3. 승인 게이트

- 호출 전에 **샷 단위 실행표**를 사용자에게 보여주고 승인을 받는다. 실행표 내용: 컷번호, 모델, 길이, 해상도, 프롬프트 전문, 첨부 프레임, 예상 크레딧.
- 승인 단위는 **에피소드 배치**로 할 수 있다(예: "ep01 1-01~1-06 승인"). 승인된 배치 안에서는 개별 확인 없이 순차 실행한다. (Q50)
- 승인 없는 시험 호출은 하지 않는다. "일단 한 번 돌려보기"는 없다.

## 4. 실행 절차 (컷 하나)

1. `file_upload`로 시작·끝 프레임 업로드 → URL → meta.json 기록
2. 호출 전 `query_membership_and_credits` → 잔여 크레딧 기록
3. `image_to_video` 호출 → generation_id 기록
4. `query_tasks`로 완료 확인 → 결과 URL 다운로드 → `outputs/<ep>/<컷>/clip_v<n>.mp4` 저장
5. 호출 후 잔여 크레딧 기록 → 클립 단가 산출(첫 호출에서 확정)
6. 06 체크리스트 B 검수 → 결과와 실패 유형을 meta.json에 기록
7. 통과: 채택. 불합격: 5절 재시도 규칙

meta.json 항목: 컷번호, 모델, 인자 전체, 프롬프트 전문, 프레임 파일명과 URL, generation_id, 결과 URL, 크레딧 전후, 검수 결과, 실패 유형, 버전.

## 5. 재시도 규칙

- 컷당 상한 **3회**(첫 생성 포함). 넘으면 멈추고 사용자에게 원인과 대안(샷 분할, 연출 변경)을 보고한다. (Q30)
- 같은 프롬프트·같은 프레임으로 재제출하지 않는다. 재시도마다 **하나씩만** 바꾼다. 순서:
  1. 프롬프트 문구 수정(끝 상태 강조, 금지 문구 추가)
  2. 끝 프레임 재생성(시작과 더 비슷하게)
  3. 길이 단축(5 → 3)
  4. 모델 변경(v3_0 → v3_0_omni 또는 o1)
- 실패 유형이 "프레임 문제"(스케일, 인벤토리)면 Kling 재시도가 아니라 Gemini 프레임부터 다시 만든다.
- 3회 실패한 컷은 `00b` B6 실패 유형표에 사례로 등록한다.

## 6. 크레딧 관리

- 첫 실행에서 클립 단가(720p 5초, 1080p 5초, 3초)를 확정해 이 문서에 기록한다.
- 에피소드 시작 전 예상 크레딧 = 컷 수 x 단가 x 1.5(재시도 여유)를 보고하고 승인받는다. (Q51: 에피소드당 상한)
- 잔여 크레딧이 예상 필요량 이하로 떨어지면 멈추고 보고한다.

## 7. Element(캐릭터 등록) 운영

- 등록 시점: 첫 에피소드 첫 둘 컷 직전.
- 등록 이미지: 커버 = 고해상도 정면, 보조 = 3/4 좌, 측면, 뒷모습. 태그 Characters.
- 비교 테스트 1회: 같은 프레임·같은 프롬프트로 등록 유무 2클립 생성(720p) → 얼굴 유지가 나은 쪽을 채택하고 이후 고정. (Q32)
- 등록 후에도 프롬프트의 캐릭터 설명은 유지한다.
- 캐릭터 바이블이 바뀌면(표정 추가 등) 재등록하지 않는다. 외형이 바뀔 때만 재등록.

## 8. 금지

- 승인 없는 호출, 시험 호출
- 오디오·멀티샷 켜기
- 10초 이상 클립(승인 없이)
- 같은 파라미터 재제출
- 사용자에게 알리지 않은 파라미터 변경
- 타임아웃·오류 시 자동 재제출(보고 후 지시 대기)

## 9. 장애 대응

- 작업이 10분 이상 완료되지 않으면 사용자에게 알리고 기다릴지 취소할지 묻는다.
- 오류 응답은 원문 그대로 meta.json에 남기고 보고한다.
- MCP 재연결 안내가 뜨면 다음 세션 시작 시 재연결을 요청한다.
